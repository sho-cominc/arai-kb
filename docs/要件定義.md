# 団体受注 管理・共有アプリ — 要件定義書 (ドラフト)

> 目的: ホテルの団体受注を、フロント・予約・セールス・料飲など**社内全体で確認・管理・進行・共有**するためのアプリ。
> 設計思想: 特定業務に作り込みすぎず、**どんな団体受注の場面でも流用できる**汎用の情報共有ツールとする。
> 作成: このドキュメントは Sho の口頭要件をもとに構造化したドラフト。合意後に確定版とする。

---

## 0. コンセプト — 「1入力 → 多出力」

このアプリの本質は **1回の入力から、必要な複数の成果物を自動生成すること**。

```
        ┌─────────────────────────────────────────┐
        │   受注入力画面(分かりやすく・漏れなく)     │
        │   ↑ 自社の料金・部屋空き状況を参照しながら   │
        └─────────────────────────────────────────┘
                          │ 1回入力
   ┌──────────┬──────────┬──────────┬──────────┬──────────┐
   ▼          ▼          ▼          ▼          ▼          ▼
社内共有ページ  調理・発注書   見積書      イベント     会場手配     カレンダー
(全部署)     (料飲/厨房)  請求書       工程表      ・共有       (全成果物を
                        領収書                              日付で俯瞰)
   │          │          │          │          │          │
   └──────────┴──────────┴─── ワンクリックで PDF / 印刷 ───┴──────────┘
```

---

## 1. 機能要件

### 1-1. 入力画面(最重要)
- **分かりやすい入力画面**があり、必要な情報を**漏らさずに**入れられること。
- **選択式 vs 自由記述の使い分け**:
  - オプションが少ない項目 → **選択式(プルダウン/ボタン)** にして入力を速く・ブレなく。
  - 融通を利かせる必要がある項目 → **自由記述・幅を持たせる**(固定化しない)。
- 入力は段階的でよいが、後工程の成果物に必要な項目が埋まっているかを可視化する。

### 1-2. 自社マスタ参照(入力を支援)
入力しながら、自社が持つデータを**すぐ確認できる**仕組み:
- **料金**(部屋・プラン・宴会・オプション等の料金表)
- **部屋の空き状況**
- ※ データ源は要決定(既存PMS〈Opera等〉連携 or アプリ内マスタ手入力)。→ 未決事項に記載。

### 1-3. 成果物の生成(入力から自動作成)
入力データをもとに、以下を作成できること。

| # | 成果物 | 主な利用者 | 用途 | 出力形式 |
|---|--------|-----------|------|---------|
| A | **社内共有ページ** | フロント / 予約 / セールス / 料飲 = 社内全体 | 案件の全体像を1画面で共有 | **Web画面(ライブ)** |
| B | **調理・発注書** | 料飲 / 厨房 / レストラン | 料理内容・数量・仕入の指示 | **Excel基本**(手で最終調整) |
| C | **見積書 / 請求書 / 領収書** | お客様向け | 金額提示・請求・受領証明 | **PDF基本**(ワンクリック・ロゴ入り) |
| D | **イベント工程表** | 運営・関係部署 | 当日のタイムライン・進行 | **Excel基本**(手で最終調整) |

### 1-4. カレンダー表示
- A〜D および案件そのものが**カレンダーで表示**され、**見落としがない**こと。
- 利用日・搬入日・イベント日・請求期日などを日付で俯瞰できる。

### 1-5. 会場手配・共有
- 施設内の**会場(宴会場・レストラン等)を手配**する仕組み。
- 手配した会場の**内容を関係部署と共有**する仕組み(ダブルブッキング防止・情報連携)。

### 1-6. 一般項目の入力と見やすい表示
入力した以下のような一般項目を、**見やすい形式で表示**できること:
- 食事の有無
- 請求方法
- 到着時刻
- 料金
- (その他、団体受注で一般的に必要な項目)

### 1-7. 出力形式(帳票ごとに分ける)
成果物の性質で出力形式を分ける。

- **お客様向け(見積書・請求書・領収書)= PDF基本**
  - **ワンクリックで PDF 化**。ロゴ入り・そのまま渡せる完成体裁。
  - 編集させない前提(値が確定した最終物)。
- **社内作業用(調理・発注書・イベント工程表)= Excel基本**
  - テンプレートExcelに入力値を流し込んで**ダウンロード → 手元で最終調整**(行追加・備考・レイアウト微修正)→ 印刷/PDF保存。
  - 現場が慣れたExcelで融通を利かせられる。
- **社内共有ページ・カレンダー = Web画面(ライブ)**
  - ファイル化せず、常に最新を全部署が画面で見る。
- 補助として、PDF基本の帳票にExcel出力を、Excel基本の帳票にPDF出力を後付けすることは可能(同一テンプレから出口を足す)。

## 2. 成果物ごとの要件(詳細)

### A. 社内共有ページ
- 1案件の基本情報・日程・人数・会場・食事・料金・ステータス・担当を集約。
- フロント/予約/セールス/料飲が同じ情報を見られる(単一の真実)。
- 更新履歴が残り、「誰がいつ何を変えたか」が分かる。

### B. 調理・発注書(料飲/厨房向け)— **Excel基本**
- 料理内容・コース・品目・**数量(人数連動)**・アレルギー・提供時刻・会場。
- 仕入/発注の指示に使える体裁。人数変更が数量に反映される。
- **Excelテンプレに流し込んでダウンロード** → 厨房で最終調整して使う。

### C. 見積書 / 請求書 / 領収書(お客様向け)— **PDF基本**
- 明細(項目・単価・数量・金額)、税、合計、支払条件。
- 見積 → 請求 → 領収 を**同じ案件データから連続生成**(再入力なし)。
- 宛名・日付・番号の管理。**ワンクリックPDF・ロゴ入り**の完成体裁。

### D. イベント工程表 — **Excel基本**
- 当日のタイムライン(時刻・内容・担当・場所)。
- 関係部署が当日の動きを共有できる。
- **Excelテンプレに流し込んでダウンロード** → 運営が最終調整して配布。

## 3. 想定データ項目(入力→各成果物へ供給)

**案件基本**
- 案件名 / 団体名
- 主催・エージェント区分
- 日程(開始〜終了・泊数)
- 人数(見込 / 確定)
- 担当者
- ステータス

**内容**
- 宿泊(部屋タイプ・室数) ← 空き状況参照
- 食事(有無・内容・時刻・会場) → 調理発注書へ
- 宴会・会場(会場名・レイアウト・時間) → 会場手配へ
- 送迎(有無・便・時刻)
- オプション(選択式)

**お金**
- 料金・料金区分 ← 料金マスタ参照
- 見積総額 / 明細
- 請求方法 / 支払条件
- 到着時刻・その他一般項目

→ これらを **必須 / 任意** に分け、選択式にするもの・自由記述にするものを次ステップで確定する。

## 4. 非機能・UX 要件
- **モバイル対応**(現場はPCの前にいない)。
- **見やすい表示**(入力値を帳票・共有ページとして読みやすく)。
- **印刷/PDFが簡単**(ワンクリック)。
- **見落とし防止**(カレンダー・通知)。

---

## 5. 確定した方針(Sho 回答済み)

1. **料金・空き状況のデータ源**: **当面はアプリ内マスタに手入力**でよい。PMS(Opera等)との自動連携は将来課題。
2. **帳票の体裁**: **読みやすければOK**(既存の固定様式に縛られない)。ただし**後からロゴを入れられる**設計にしておく(ヘッダーにロゴ画像を差し込めるテンプレート)。
3. **会場手配**: **ダブルブッキング判定は必要**。いずれにせよ**カレンダーが必須**(会場×日時で空き/重複を可視化・警告)。
4. **ブロックコード採番**: 会計側の固定ルールは今は無い。ただし **Opera運用向けに「10桁・英数字」のブロックコードを自動生成**したい。入力内容に応じて、人が見て意味を推測できる"気の利いた"コードを生成するのが理想。→ 詳細は §7。

## 6. 会場手配・カレンダー(要件詳細)
- **会場マスタ**: 施設内の会場(宴会場・レストラン等)を登録(名称・定員など)。当面手入力。
- **カレンダー**: 会場 × 日時で予約状況を表示。案件から会場を押さえると、その枠がカレンダーに反映される。
- **ダブルブッキング判定**: 同一会場・同一時間帯に別案件が入ろうとしたら**警告**(または登録をブロック)。
- 手配内容(会場・時間・レイアウト・人数)は関係部署と共有される。

## 7. ブロックコード自動生成(Opera向け・10桁英数字)
入力内容から、意味が読み取れる10桁の英数字コードを自動生成する。

**目的**: Opera 等での識別に使える、人が見て中身を推測できるコード。

**生成案(いずれか要決定)**
- **案A(日付先頭・6+4)**: `YYMMDD` + グループ略号2字 + 連番2桁
  例) 2026-08-15 田中様 → `260815TA01`
- **案B(略号先頭・読みやすさ重視)**: `MMDD` + グループ略号4字 + 連番2桁
  例) 8/15 TANAKA → `0815TANA01`
- **案C(種別+日付)**: 種別1字(W=婚礼/M=MICE/T=ツアー等) + `YYMMDD` + 連番3桁
  例) 婚礼 2026-08-15 → `W260815001`

**共通ルール(たたき台)**
- 全て**大文字英数字**、ちょうど**10桁**。
- グループ略号は団体名から自動抽出(ローマ字化・母音圧縮等)、手修正も可能。
- 連番で重複回避。生成後は**手動編集可**(自動はあくまで初期値)。
- → どの案を基本にするか、種別コードの割り当てを次で確定する。
